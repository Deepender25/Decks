What is Bias? When the Model is Too Simple

UNDERFITTING GRAPH
"Bias is the error that happens when a model is too simple to capture the important patterns in the data."
•Makes strong or overly simple assumptions about the data.
•Misses important patterns and fails to learn enough.
•Consistently leads to Underfitting.
Simple Example: Imagine the true relationship is a curve. If we force a straight line through it, the model is too simple to follow reality.
High Bias = Too Simple = Underfitting
UNDERFITTING VISUALIZATION
"The dots represent actual data. The curved pattern is what the data is really doing. But our model uses a straight line and fails to follow the pattern."
Student 1 • Defining Bias and Underfitting

What is Variance? When the Model is Too Sensitive

OVERFITTING GRAPH
"Variance is the error that happens when a model learns the training data too closely, including its noise and small irregularities."
•Model is too complex and overly flexible.
•Learns noise instead of discovering the general pattern.
•Performs great on training data, but poorly on new data.
•Directly leads to Overfitting.
High Variance = Too Complex = Overfitting
OVERFITTING VISUALIZATION
"The model is too flexible. Instead of learning the general pattern, it tries to match every training point. Predictions on new data become poor."

The Problem: Why Is There a Tradeoff?

THE COMPLEXITY LEVER
"We want both Low Bias and Low Variance. But changing model complexity pushes them in opposite directions."
•As model complexity increases:
Bias decreases (↓) — the model gets better at capturing patterns.
Variance increases (↑) — the model becomes sensitive to training noise.
Making a model more complex reduces bias, but increases variance.
MODEL COMPLEXITY SPECTRUM DEGREE d = 3
Model Capacity Sweet Spot (d=3)
d=1 (Simple) d=3 (Sweet Spot) d=10 (Complex)
☆ BALANCED SWEET SPOT (OPTIMAL GENERALIZATION)

Optimal model capacity captures natural quadratic structure while filtering noise.

How Do We Balance Bias and Variance?

THE THREE PILLARS
"There is no single perfect model for every dataset. We try to find a model that is complex enough to learn the important patterns, but simple enough not to learn unnecessary noise."
PILLAR 01 CAPACITY

1. Choose Appropriate Model Complexity

Don't use an unnecessarily simple or complicated model. Match algorithm capacity to the true scale of the problem.

☆ PILLAR 02 VALIDATION

2. Use Cross-Validation

Test the model on different portions of data to see how consistently it performs on unseen samples.

PILLAR 03 PENALTY

3. Use Regularization

Add a mathematical penalty for unnecessary model complexity to prevent the model from overfitting to noise.

STUDENT 3

Practical Techniques: The ML Toolkit

TOOLS WE USE
🔄 CROSS-VALIDATION

Split data into multiple parts ($K$-folds) and train/test in different combinations.

Purpose: Check whether model performs consistently on unseen data.
⚙️ REGULARIZATION L1 / L2

Add a mathematical penalty for unnecessary model complexity (e.g. Lasso & Ridge).

Loss + λ × (Complexity Penalty)
Purpose: Prevent the model from becoming too complex or wild.
🌳 CONTROL MODEL CAPACITY HYPERPARAMETERS

Limit decision tree depth, choose appropriate polynomial degrees, select key features.

• Tree Depth Limits • Feature Selection
Purpose: Keep the model at an appropriate level of complexity.
📚 MORE REPRESENTATIVE DATA DATASET

More useful and representative training examples can help the model learn the real pattern.

Diverse Samples → Noise Drowns Out
Purpose: Learn the real underlying pattern rather than random noise.
